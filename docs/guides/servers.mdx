# Configure A2A servers

Handler can load configured A2A server definitions from two places:

- global config in your user configuration directory
- repo-scoped config at `.handler/servers.toml` in the repository root

The global file lives where your platform keeps per-user configuration:
`~/Library/Application Support/handler/servers.toml` on macOS,
`$XDG_CONFIG_HOME/handler/servers.toml` on Linux (`~/.config/handler` when
the variable is unset), and the local AppData directory on Windows.
`handler server validate` prints the path of every file it read.

Repo-scoped config is useful when a project should travel with a shared
agent URL or auth shape, while secrets continue to come from environment
variables on each developer machine.

## File format

```toml
version = 1

[servers.local]
url = "http://localhost:8000"
```

Each server entry needs a `url`. Auth and extensions are optional.

## Global vs repo-scoped

Use global config by default:

```bash
handler server add demo --url http://localhost:8000
```

Use repo-scoped config when the server definition belongs with the repo:

```bash
handler server add demo --url http://localhost:8000 --repository
```

## Request extensions on every call

If an agent expects an A2A extension, list its URI on the server entry and
Handler sends it in the `A2A-Extensions` header on every request to that
server. Extensions given on the command line with `-e/--extension` are merged
in.

```toml
[servers.demo]
url = "https://agent.example.com"
extensions = ["https://example.com/extensions/traceability/v1"]
```

When a card marks an extension as required and the entry does not request
it, Handler warns on connect.

## Validation helpers

Handler validates server files when it loads them and skips only the invalid
entries instead of failing the whole file.

Use these commands to inspect what is available.

List every configured server Handler can load:

```bash
handler server list
```

Show one server's resolved configuration:

```bash
handler server show demo
```

Validate configured servers and auth references:

```bash
handler server validate
```

## Example with auth

```toml
version = 1

[servers.demo]
url = "https://agent.example.com"
extensions = ["https://example.com/extensions/traceability/v1"]

[servers.demo.auth]
type = "bearer"
env = "HANDLER_DEMO_TOKEN"
```

See [Authentication](./authentication) for all six auth types.
